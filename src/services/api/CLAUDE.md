# Multi-provider routing

Backend via `CLAUDE_CODE_USE_OPENAI`/`_BEDROCK`/`_VERTEX`/`_FOUNDRY` (default Anthropic); wiring in `src/services/api/`. Anthropic-compatible third parties (Kimi, MiniMax, DeepSeek…) use profiles in `~/.noa/provider-profiles.json` (Bearer `ANTHROPIC_AUTH_TOKEN`). Unknown OpenAI-compatible models → 128k context (`src/utils/context.ts`). Only the OpenAI shim sends `store: false`; it isn't an Anthropic Messages field. The shim translates `output_config.effort` → `reasoning_effort` when the profile declares levels for the model (DeepSeek's preset), or when `CLAUDE_CODE_OPENAI_REASONING_EFFORT` opts an undeclared endpoint in; a declared `max` is passed through rather than clamped. `reasoning_content` streams become thinking blocks marked with an `openai-chat-reasoning:<host>` signature and are replayed as `reasoning_content` on tool-call turns only, which DeepSeek documents as required. Resume and compaction keep the blocks whose host matches the active endpoint; a provider switch strips them all. A 400 naming an optional request field is latched per provider/base URL/model in `src/services/api/requestLatches.ts` and left out on retry; a new optional top-level field heals only if listed in `OPTIONAL_ROOTS`.

Anthropic-compatible profiles declare optional thinking with `thinkingModels` and mandatory thinking with `rejectsDisabledThinkingModels`; the latter forces thinking on in main and side-query requests and prevents the UI from disabling it. Both lists are endpoint-scoped and reset when the endpoint changes.

The `chatgpt` profile type sets `NOA_CLAUDE_OPENAI_AUTH=chatgpt`: the shim then posts to `/responses` (`openaiResponses.ts`) with an OAuth token from `chatgptAuth.ts`, never `/chat/completions`. That route rejects `max_output_tokens`, `temperature`, `top_p`, `metadata` and `previous_response_id`, so don't add them there. Reasoning items ride in the thinking block's `signature` under an `openai-reasoning:` prefix and are replayed on the next request. Effort levels for GPT models on this route come from the version ladder in `getGptResponsesEffort` (`src/utils/effort.ts`); no effort is sent by default, so OpenAI's per-model default applies. Prompt caching on this route keys on the `session-id` header, and `tools` heads the cache prefix. Tool search is off on every OpenAI-compatible route unless `ENABLE_TOOL_SEARCH` is set: the shim can only flatten `tool_reference` to text, and a discovered tool would re-bill the whole conversation. Anthropic's `web_search_*` server tool (WebSearch's sub-request) is sent there as OpenAI's hosted `{type: "web_search"}`, and its `web_search_call` items and `url_citation` annotations come back as `server_tool_use` / `web_search_tool_result` blocks. Gemini's OpenAI-compatible endpoint rejects `google_search`, so WebSearch calls native `generateContent` instead (`src/tools/WebSearchTool/backends.ts`).
